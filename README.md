# Решение домашнего задания по теме: «Протокол HTTP. Вызов удаленных серверов»

## Реализация + общие мысли

- В качестве дополнительной задачи, не стал использовать рекомендованную зависимость `org.apache.httpcomponents`, а написал клиента через стандартную библиотеку `java.net.http.HttpClient;`
    - Для создания экземпляра использовал паттерн builder - `newBuilder`,  вынося его во вспомогательный метод `getHttpClient`, попутно познакомившись с абстрактным классом Duration библиотеки java.time;
    - В отличие от библиотеки `org.apache.httpcomponents`, возможность настройки архитектуры клиента несколько отличаются, например: нельзя по-умолчанию указать таймаут сокета, только под конкретный запрос;
- Некоторый момент из записи вебинара, а именно аргумент метода readValue, вызываемый на экземпляре класса ObjectMapper: new TypeReference<List<CatsGrade>>() {}, заставил идти читать про type erasure;
- Получение данных с сервера решил не писать в String, так как на мой взгляд это не лучшая практика, в силу того, что строка может быть огромной и вызвать при негативном сценарии - OutOfMemory. Попробовал реализовать на уровне потока байт;
- При оформлении итогового вывода, добавил сортировку в Stream API по убыванию относительно голосов для наглядности;

## Проблемы

- Старался своими силами пользоваться javaDoc с целью решения задачи средствами стандартной библиотеки, столкнувшись с некоторым объемом зависимостей, что значительно осложнило пути создания объекта запроса к http серверу, в особенности применения настроек.
- Наступил на грабли испльзования компаратора при сортировке, а именно допустил ошибку и не использовал механизм, защищающий от переполнения `integer overflow`
- Очередной раз возвращался к теме байтовых потоков, требуется дополнительное закрепление вопроса буферизации.
